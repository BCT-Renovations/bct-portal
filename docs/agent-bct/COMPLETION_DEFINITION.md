# Agent BCT Completion Definition

Agent BCT is not “done” because code exists. Completion requires evidence across each gate.

## Secure backend
- fixed server boundary and role resolution;
- approved maintainable knowledge;
- bounded read tools;
- no arbitrary RPC/SQL;
- human authority preserved;
- safe audit/escalation path;
- estimator backend mismatch resolved before estimator live tools;
- durable production rate limiting.

## AI behavior
- current preview model/provider configuration verified;
- Phase A generation adversarial tests passed;
- Phase B read tools passed cross-user/cross-role/RLS tests;
- high-risk reads separately passed;
- supported-language generation tested;
- no secret/prompt/bid leakage;
- safe outage/budget/rate behavior.

## Product
- mobile Agent UI integrated without breaking existing portals;
- logout/account switch isolation;
- keyboard/scroll/back/accessibility/RTL behavior;
- transparent Agent BCT identity;
- voice only after secure text foundation and its privacy decisions.

## Release
- exact candidate SHA has CI evidence;
- exact candidate SHA has READY preview;
- V46 regression passes;
- iPhone verification passes;
- Integration Contract current;
- complete/remaining report prepared;
- production merge/deployment waits for Ty Perry's explicit approval.

A blocked infrastructure gate is BLOCKED, not PASS. A design document is not execution evidence.
